# Q-Pixelate 首版设计

日期：2026-11-19

状态：用户已于 2026-11-19 回复“开始吧”批准；首版已实现，验证记录见 ../../verification.md（项目内 docs/verification.md）。

## 目的

为长时间游戏录屏提供局部修订工具：在源视频时间轴上选择少量片段，为其添加全屏模糊、固定区域模糊或图片遮挡，再导出完整视频。主要收益是无需重新编码未修改的大部分视频。

用户已明确：首版使用固定遮挡区域，移动目标通过拆分片段处理，不做自动跟踪。

## 实现路线

已提出两条路线：

1. PySide6 + FFmpeg：本地桌面界面，直接访问大文件，依赖较少；需要自行实现时间轴和区域编辑。
2. Electron + FFmpeg：网页技术适合复杂时间轴，安装体积和内存开销更大。

开发方推荐并拟采用第一条路线。理由是目标环境是 Windows，当前 Python 3.12、PySide6/QtMultimedia 6.11 和 FFmpeg/ffprobe 8.0.1 均已可用。技术选择尚未被用户单独确认，不把它记为用户要求。

## 交付目标

- 可从项目启动的 Windows 桌面程序，中文界面。
- 可复现的依赖与启动说明；提供一键启动脚本。
- 可导入本地视频、编辑多个修订片段、预览效果、保存和载入工程、导出完整成片。
- 为导出核心提供自动化验证，使用生成的小型视频检验实际输出。
- 打包为独立 exe 属于后续分发工作，首版不依赖先完成打包才能使用。

## 编辑流程

1. 打开视频，后台读取时长、尺寸、帧率、编解码信息、音轨及关键帧索引。读取和索引不阻塞界面。
2. 播放或拖动定位；通过入点、出点创建修订片段，支持直接输入时间。
3. 给每个片段设置一种效果：全屏模糊、区域模糊、图片遮挡。
4. 区域效果可在画面上拖出矩形，并拖动位置、调整大小；可通过数值微调。存储源画面归一化坐标，窗口缩放和预览黑边不改变遮挡位置。
5. 选择片段进行效果预览，确认生效时间与遮挡范围。
6. 选择新输出路径，查看快速导出的处理范围与兼容性检查结果，开始导出。
7. 显示进度、当前阶段、取消按钮及结果。完成后可打开输出目录。

首版每个修订片段设置一种效果。支持多个不重叠修订片段；时间区间重叠时明确提示用户合并或调整，不擅自决定效果叠加顺序。相邻片段允许共享边界。

## 界面与操作

- 中央视频预览，底部时间轴，右侧片段列表与效果参数。
- 时间轴显示总时长、播放位置、选区、已添加片段；支持缩放、拖动定位和选区边界调整。
- 空格播放/暂停，I/O 设置入点/出点，左右方向键定位相邻帧，Delete 删除选中片段。
- 全屏模糊和区域模糊可设置强度；图片遮挡可载入 PNG/JPEG，调整位置和尺寸，保留 PNG 透明度。
- 片段列表显示起止时间、时长、效果，可选择、修改和删除。
- 播放期间显示当前片段和遮挡范围。编辑模式明确标记为原画加遮挡框；不能把仅显示矩形边界的画面称为实际打码预览。
- 提供“预览该片段”：用与导出相同的 FFmpeg 效果生成低分辨率临时预览，在程序中播放。预览参数或素材变化后缓存失效。此方式可以验证真实模糊和透明图片效果，不需要编码整个源视频。

## 快速导出原理

用户选择的效果时间与实际需要编码的时间分开保存：

- 效果时间：遮挡真正出现和结束的区间，按源视频时间定义，使用左闭右开的边界。
- 编码时间：为获得可独立解码的边界，向外扩展到可用随机访问关键帧的区间。编码区间相交时合并，避免重复、遗漏或重复编码同一段。

举例：用户只给 10:00–10:05 打码；如果关键帧要求编码 09:58–10:06，只有这八秒重新编码，模糊仍只出现在指定的五秒内。

导出过程：

1. 检查源文件、输出路径、效果范围、图片素材、编码器和可用临时空间。
2. 建立互不重叠的复制区间与局部编码区间。
3. 未修改区间直接复制压缩视频流；局部编码区间解码、按原时间应用滤镜，再编码为匹配源流的设置。
4. 拼接视频，统一处理片段时间戳，保留总时长。
5. 画面编辑不改变时序，因此最终复用源文件的完整音轨，避免音频反复切割和编码；首版保留全部兼容的音轨和语言标签。不承诺保留章节、附件和字幕，检查摘要中明确列出实际保留的流。
6. 校验输出，再将临时成片移到用户指定的新文件。导出失败或取消时不把半成品当成成功结果。

没有修改片段时可以直接流复制导出。源文件不覆盖，输出已有文件时要求用户明确确认覆盖。

## 兼容性与限制

首版优先验证常见的 H.264、8-bit SDR、逐行、固定帧率录屏（MP4/MKV 输入）。容器扩展名相同不代表编码流兼容。

快速导出必须检查分辨率、编码格式、Profile/Level、像素格式、帧率、时间基准、色彩信息、旋转及关键帧条件；参数匹配不能替代实际接缝验证。切割时要考虑 B 帧的解码时间与显示时间，不能通过整数秒四舍五入拼接。

H.265、可变帧率、HDR、10-bit、带旋转、非零起始时间等输入应先探测。对尚未验证的条件，明确说明不能使用首版快速导出。允许提供用户主动选择的“兼容导出”，该模式完整重编码并清楚显示耗时差异；绝不在快速模式失败后悄悄改为全片重编码。

精确支持范围由真实集成测试结果确定；某种输入在测试中无法保证正确时，缩小快速模式支持范围并给出原因，不能通过隐藏错误或只改变文件扩展名绕过检查。

所有转码、索引、预览任务使用后台工作线程或子进程，支持取消。构造 FFmpeg 参数使用参数数组，不把文件路径拼成 shell 命令。中文路径、空格、引号、逗号等特殊字符要验证。

## 工程与临时文件

- 工程采用带版本号的 JSON，保存源路径、源文件大小和修改时间、片段区间、效果参数、区域位置、图片路径。
- 工程里的视频和素材优先用相对工程目录的路径；载入时解析并验证。源文件发生变化时阻止沿用旧索引导出，提示重新载入。
- 修改工程后提供未保存提示；工程校验失败时提示可理解的错误。
- 临时目录每次任务独立创建，只清理本任务创建的文件，不删除源视频、图片或用户其他文件。
- 导出记录可查看的 FFmpeg 日志与错误说明。

## 验证与验收

自动生成带时间标记、运动画面和音频的短测试视频，覆盖：

- 无编辑流复制；全屏模糊；区域模糊；PNG 透明图片遮挡。
- 一个片段、多个片段、相邻片段、多个片段共用同一个关键帧编码区间。
- 片段位于开头或结尾、边界不落在关键帧、带 B 帧的输入。
- 源视频无音轨、多音轨、不同的常见固定帧率。
- 中文和带空格的路径、工程保存载入、素材丢失、取消和失败清理。

验收不仅检查 FFmpeg 返回码，还检查实际输出：可解码、时长和帧数符合预期、接缝无丢帧/重复帧、音画同步未改变、指定区间外没有遮挡、指定区间内效果出现。通过日志和区间计划验证只重编码了局部范围。

同时进行一次真实桌面操作验证：打开测试视频、设置入出点、框选区域、生成效果预览、保存载入工程、导出并播放结果。
