# Q-Pixelate 便携启动器、组件管理与自动马赛克

日期：2026-11-20

状态：已获用户批准。采用 PyInstaller 轻量独立启动器与按需下载组件。

## 目标

在干净的 Windows x64 电脑上双击启动器即可检测环境，并一键补齐打开视频和导出需要的组件。自动识别环境和两个模型由用户按需安装或卸载。识别在本机完成。用户可在选区内扫描裸露画面，复核时间和位置标注，再一键将勾选结果转换为马赛克图层。

目前的源码启动脚本依赖系统 Python 和 PySide6，视频工具通过 PATH 查找，贴纸库位于用户数据目录。工程保存素材路径和视频指纹，因此移动程序与移动工程是两件事。首版的发布和验收范围为 Windows 10/11 x64，继续沿用当前视频格式与快速导出限制。

## 发行方式

| 方案 | 取舍 |
| --- | --- |
| 轻量启动器与按需组件，已选择 | 首次只分发 PyInstaller 打包的启动器、发行清单和必要说明。第一次使用时下载缺少的组件，也可导入离线包。 |
| 完整离线便携包 | 干净电脑解压即能打开视频，代价是每位用户都要下载完整基础环境。后续可用同一套组件另做离线分发。 |

启动器使用标准库、Tkinter 和 Windows 系统能力，以 PyInstaller 单文件模式生成 `Q-Pixelate.exe`。基础编辑器包包含 Q-Pixelate 编辑器代码、与之匹配的私有 Python 3.12 x64、PySide6 和 Qt Multimedia 插件。除启动器自己的 Python 和 Tk 运行库外，其他运行时由组件管理器安装。启动器直接运行私有 `pythonw.exe`，并传入使用者双击或拖入的视频参数。组件路径以发行目录为根，使用启动器实际所在位置定位。源码启动方式保留给开发者。

发行清单随构建生成，记录版本、架构、依赖、下载地址、字节数和 SHA-256。构建时生成基础运行环境包、CPU 识别包和 GPU 加速包，在构建产物中列出这些包和对应的许可证。FFmpeg 从已验证的 Windows 构建获得，固定版本并保留许可文件。NudeNet 模型使用锁定版本的上游 ONNX 文件。首次联网的发布版需要可访问的组件发布地址。构建配置接受发布地址作为参数，本地验收可以使用构建产物搭配测试服务器或离线导入。本文不包含对外发布操作。

## 首次安装与设置

启动器先检查 Python 和 PySide6 能否启动、FFmpeg 与 ffprobe 能否运行，以及 FFmpeg 是否具备现有导出需要的编码器与滤镜。缺项时默认勾选基础组件，可在同一页选装自动识别。点击「下载安装所选项」后显示下载、校验、安装和验证进度，验证通过即可启动编辑器。只有识别组件缺失时可直接进入编辑器。

编辑器顶部提供「设置 → 环境与组件」。它与首次启动向导共用组件清单和管理逻辑。各组件显示来源、版本、下载大小、已安装占用和状态，并提供重新检测、安装、修复、卸载及导入离线包。发行版中，需关闭编辑器的操作交还启动器执行，关闭前沿用现有工程保存流程。源码启动时，页面将当前 Python 显示为外部环境，仍可管理视频和识别组件。

| 组件 | 规则 |
| --- | --- |
| 基础运行环境 | 编辑器必须有兼容运行环境。发行版默认使用软件私有副本，移除后可从启动器重装。 |
| FFmpeg / ffprobe | 作为一组安装和验证。可指定用户已有的工具目录，源码启动继续支持 PATH。解除引用和删除软件自带副本分别处理。 |
| CPU 识别环境 | 安装 NumPy、OpenCV 与 CPU 版 ONNX Runtime。配合任意已安装模型即可扫描，不要求独立显卡。 |
| NVIDIA 加速环境 | 独立安装匹配的 ONNX Runtime GPU、CUDA 和 cuDNN 运行库。安装后用测试输入执行一次实际推理，显示使用的执行设备。GPU 不可用时显示原因，并在 CPU 环境已安装的情况下可切换到 CPU。 |
| NudeNet `320n` 和 `640m` | 分开下载、选择、删除，约 12 MB 和 104 MB。允许同时安装。单次扫描使用一个模型。 |

组件安装在程序旁的私有 `components` 目录，配置保存组件的相对位置。发行目录需要可写，遇到只读目录时启动器会提示解压到可写位置。CPU 与 GPU 运行库各有独立目录，在各自的识别子进程中载入，避免两个 ONNX Runtime 版本冲突。使用绝对路径启动已选定的 FFmpeg 和 ffprobe，无需修改系统 PATH，也无需管理员权限。显卡驱动由用户维护，启动器只报告兼容性。

下载到同一磁盘的临时目录，校验后解包与试运行，全部通过再切换到新版本。取消、网络失败或校验失败保留可用旧版本。离线包使用同一清单和校验流程。每次只允许一个组件变更任务，卸载只处理软件管理的目录。程序目录可连同组件整体搬迁，贴纸库继续使用现有用户数据位置。迁移工程时仍需携带源视频和贴纸，并保持工程记录的相对路径。

## 自动识别与马赛克

1. 建立或选中未锁定的选区，点击「识别裸露内容」。组件缺失时，从这里直接进入组件设置。模型和 CPU/GPU 选择来自设置页，并在扫描开始前展示当前选择。
2. 使用后台任务和独立识别进程流式解码选区。首版在扫描前检查现有快速导出的格式和帧索引条件，遇到可变帧率、旋转或异常时间戳时给出原因。每个结果包含原视频时间、原画面的归一化矩形、类别和置信度。提供快速扫描和逐帧扫描两种模式，默认给定可调整的快速扫描频率。精确起止边界以源视频帧索引为准。进度和取消沿用现有任务区，取消或失败时不改动既有图层。
3. 将连续出现的相同目标归为可复核的标注，保留位置随时间变化的数据，允许同一时刻多个目标。避免跨镜头连接目标，不对长时间未命中的区间延伸标注。快速扫描可能漏掉短画面，界面显示已扫描的模式和结果。无命中时显示「未检测到」，结果列表支持逐项勾选、跳转和在画布查看坐标框。未应用的标注是当前会话的审核草稿，切换选区后仍可回来查看，关闭工程前需应用才能随工程保存。
4. 点击「全部马赛克」，为当前已勾选结果批量生成可编辑的块状马赛克图层。同一批只添加尚无对应图层的结果，删除后可重新应用。重新扫描会刷新待审核结果，已应用的图层由用户管理。选区范围改变后，当前检测结果失效，需要重新扫描。
5. 短采样间隔内对同一目标的矩形边缘进行插值。图层几何编辑对整段轨迹应用平移或缩放。用户移动图层时间时轨迹随之移动，调整端点时按新边界裁切，主动延长到轨迹外时沿用最近一端的矩形。主编辑画布用于查看轮廓，现有「预览当前片段效果」用于检查实际马赛克。
6. 已应用图层随工程保存，记录时间、像素块大小和遮罩位置随帧变化的数据。使用向后兼容的读取流程，旧工程保留原效果。效果预览和导出共用渲染逻辑，按源时间应用马赛克，再执行变速；只有相关编码区间进入局部重编码。卸载模型或识别运行库后，已保存的图层仍可编辑、预览和导出。

识别首版使用 NudeNet，默认检测需要遮挡的裸露类别，排除面部、脚、腹部等无关类别。模型效果以代表性素材评估。游戏和动画画面可能需要调整阈值，仍由用户复核。扫描频率、置信度、区域扩边和跨帧关联参数由实现阶段通过测试确定；参数选择以减少漏挡、维持可接受的误报和耗时为准。

## 验收

- 干净 Windows x64 环境未安装 Python、Qt 或 FFmpeg 时，双击 `Q-Pixelate.exe` 可启动检测页，安装必需组件并打开视频。重复启动可离线运行。已安装组件的应用目录换位置后能继续使用。
- 启动器和编辑器看到同一组件状态。损坏包、取消、断网和重试不会破坏旧安装。离线包能完成同一安装流程。卸载只移除产品安装的内容。
- CPU 执行一次模型推理。具备兼容 NVIDIA 环境时实际验证 CUDA 推理。分别记录测试素材的扫描耗时及峰值内存或显存。
- 使用可复现的视频与已知矩形结果，核对时间点、多目标、目标移动、应用去重、选区变动、保存后载入，以及实际导出帧的马赛克边界。模型卸载后重新打开工程，验证预览和导出无需识别组件。
- 跑现有工程、界面和渲染回归测试，至少验证一段短 H.264 视频在选区内外的处理范围以及源视频尺寸和音轨。
